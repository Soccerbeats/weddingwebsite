**Date:** 2026-08-25 (UTC) · **Version audited:** v0.9.41 (`52e2bb8`) · **Method:** static read of every file under `src/`, `database/`, `docker/`, `.github/`, plus the project's own check suite (`check:types`, `lint`, `check:changelog`, `check:photos`, `check:finance`, `check:finance:ui`, `check:honeymoon`).

Nothing was changed in the code. Every item below is **Open** unless marked otherwise. Items marked **Verify** are things the code strongly suggests but I could not exercise against a running instance tonight.

Not read line-by-line (covered by passing test scripts): `src/lib/finance.ts`, `src/lib/changelog.ts`, the seeds (`demoSeed.ts`, `honeymoonSeed.ts`, `honeymoonCoords.ts`) and the `scripts/` themselves.

## 3. Details and suggested fixes

### Critical

**B-01 — RSVP PUT is an IDOR.** `src/app/api/rsvp/route.ts` PUT trusts `body.id`. Fix: derive the row server-side — look up the RSVP by the verified `guest_list` primary name (the same query `guest-verification` uses) and ignore the client id; or issue a short-lived signed token at verification time and require it on POST/PUT.

**B-02 — RSVP POST creates guests.** The `else` branch INSERTs into `guest_list` when no match exists. Fix: require a match (return 404 "not on the guest list") — the form already gates on verification, the API doesn't. Add a simple per-IP rate limit on `/api/rsvp` and `/api/guest-verification` (in `middleware.ts`, since it already covers `/api/*`).

**B-03 — JWT secret.** Use a dedicated `JWT_SECRET` env var, refuse to start (or refuse to mint tokens) when unset, and read it from one module (`src/lib/auth.ts`) instead of five copies. Rotating the admin password would then not invalidate sessions, which is a side benefit.

### High

**B-04 — "Make changes" after first RSVP.** `RSVPForm.tsx:303` → `setExistingRsvp({ ...existingRsvp, id: existingRsvp?.id })`. When `existingRsvp` is null this yields `{ id: undefined }`, `isUpdate` becomes true, PUT is sent without an id, server returns 400. Fix: have POST return the new row id and store it (`setExistingRsvp({ id: data.id, ... })`), or re-run verification on "Make changes".

**B-05 — "Sarah & James".** Load `getSiteConfig()` in the route and use `${brideName} & ${groomName}` for `from`, body and signature. Also use `weddingDate` in the confirmation.

**B-06 — Placeholder copy on /schedule.** The Shuttle Service and Dress Code cards are literals. Either make them config fields (`scheduleShuttleText`, `scheduleDressCode`) with an admin editor, or remove the cards until there is real content.

**B-07 — Seating stats.** Either give tables a real capacity (Add Table modal asks "how many seats?", PATCH `seat_count`, dashboard uses it and flags over-capacity) or have the dashboard use `assigned` as the denominator like the seating page does. Today the two disagree.

**B-08 — Static `/config/photos.json`.** Change `PhotoGallery` to fetch `/api/admin/photos` — but that route is admin-only and returns un-hearted photos too, so add a small public `GET /api/photos` (hearted + ordered only). Note the public GET also fixes the "GET writes photos.json" side effect for guests.

**B-09 — site.json races.** Put every write behind one helper in `lib/config.ts`: `updateSiteConfig(mutator)` that serialises via a module-level promise queue and writes `site.json.tmp` then `rename()`. Same for `photos.json` and `timeline.json`. Have editors PATCH only the keys they own (the Settings, About, Colour, Home, Wedding Party and FAQ pages currently POST the entire config they loaded on mount).

**B-10 — HeartBurst.** Track two `touchend`s within ~300 ms before spawning, or drop the touch path.

**B-11 — Day deletion.** After `remove('days', id)`, reorder the remaining ids (`api.reorder('days', rest)`) so numbering closes up — that is what drag does. `CalendarView` should use `Math.max(day_number)` rather than `days.length`.

**B-12 — createCategory.** Check for the unique-violation explicitly (return the existing key on 409 from the API) instead of treating 500 as success.

**B-13 — WIP gating.** Move the check into `middleware.ts` (it already runs for `/admin` and `/api`; extend the matcher to the public pages, query `wip_toggles` via a cached fetch to `/api/wip-status`, and redirect server-side). Then update AGENTS.md.

**B-14 — Seating party members.** Use `guest.party_members[i].name` for extra seats before falling back to "X's guest n". `GuestListEntry` needs the `party_members` field.

**B-15 / B-89 — Red checks.** Fix the two `.mts` files (add `archived: false` to the fixture; type the Playwright callbacks or move that script behind an optional dep), then add `npm run lint && npm run check:types && npm run check:changelog && npm run check:honeymoon && npm run check:finance && npm run check:photos` to the CI `build` job so it cannot regress.

**B-16 — Login brute force.** A tiny in-memory counter per IP in `auth/login` (e.g. 10 attempts / 15 min) is enough for a single-instance site.

**B-17 — Verification leaks contact details.** Return only what the form needs to prefill (`existingRsvp.email/phone` are already prefilled from the RSVP, so `guest.email/phone` can go), or return them only after a second factor (e.g. the invitation code). Design call.

### Medium (selected detail)

**B-18** — Make POST upsert on `LOWER(guest_name)` (one RSVP row per household) or have verification always return the latest row and the form always PUT. Dashboard counts should then be correct without dedupe logic.

**B-22** — Move `CREATE UNIQUE INDEX` into `init.sql` (after a one-off dedupe) and out of the request path; with the index in place, `upsert` works and the DDL stops running on every add.

**B-23** — Copy the `CREATE TABLE IF NOT EXISTS` blocks from `financeDb.ts` and the `honeymoon_categories` block from `honeymoonDb.ts` into `init.sql`. Both files say "must stay in step" — they don't.

**B-24 / B-25 / B-26** — One `safePhotoPath(name)` helper (basename only, `startsWith(PHOTOS_DIR + sep)`, extension whitelist, size cap) used by every upload/delete route. Reject `.svg` or serve it as `application/octet-stream`.

**B-27** — Resolve the hostname and refuse private/loopback ranges before fetching; cap body size; restrict `expandShortLink` to hosts `goo.gl` / `maps.app.goo.gl` exactly.

**B-28 / B-29** — Wrap `assign` in a transaction; add a `PUT /api/admin/seating/tables/[id]/seats` that replaces the seat list atomically; stop overwriting `seat_count` in the floor-plan GET.

**B-30** — Return 400 when `parseAmount` yields null for a `number`/`int` field instead of writing 0.

**B-33** — Add `IDR: 'Rp'` to `CURRENCY_SYMBOLS`.

**B-34** — Use pointer capture on the grid and `document.elementFromPoint` in `pointermove` to find the hovered cell; drop `onPointerLeave` commit.

**B-35** — Have `CategorySelect.onCreate` call `api.createCategory(typed)` and return its key.

**B-41** — Read DATE columns as text (`start_date::text`) or set `pg.types.setTypeParser(1082, v => v)` in `lib/db.ts` so dates never pass through a JS Date.

**B-46** — Link to `/#faqs` directly, or make `/about` preserve the hash.

**B-47** — Store `weddingDate` as `YYYY-MM-DD` and `weddingTime` as `HH:MM` (date/time inputs in Settings), build the Date from parts. Add a "We're married!" state.

**B-50** — Add the question locally and save only on the Save button, or save with empty strings and hide empty FAQs on the public page.

**B-51** — Add a `keydown` Escape listener when `roomEditMode` is true, or remove the sentence from the legend.
